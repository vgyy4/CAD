# Fusion design streams: what is in the files (byte coverage)

How much of a Fusion 360 design stream the Gusset reader understands, measured byte by byte
over the sample corpus. Clean-room: the layouts come from sample bytes only
(`fusion-design-stream.md`); no sample bytes are kept here beyond short field examples, and
designs are named by sample set and leading number only.

## The dumper

`gusset_sat::fusion_tree::coverage` runs the ordinary reading of a design (the feature tree, the
pattern copies and the placements, exactly the calls an import makes) with byte recording on
(`gusset_sat::cover`), adds the framing every record has, and tiles every BulkStream record into
spans:

- **decoded**: taken by a field a reader knows. The readers name their fields where they accept
  a value (`point.xyz`, `extrude.operation`, `loop.curve-ids`, `placement.matrix`, ...); the
  framing names are `header.*` (tag, id, zero, flags, attributes), `section.*` (section heads),
  and the generic `ref`, `wstr`, `own-id`, `list.count` (references, UTF-16 strings and
  reference lists a reader walked). A reader's own name wins over a generic one for the same bytes.
- **known-skipped**: bytes a reader steps over knowingly (`list.pad`, `extrude.kind-flags`,
  `line.unread-doubles`, `loop.curve-unread-*`, `feature.name-gap`, `drill.zeros`, ...).
- **unknown**: everything else. The listing shows them in hex with guesses: references (with
  the target's class), UTF-16 and ASCII strings, doubles of plausible size, the `u32`s at the
  span's start, and any double or `u32` that equals a model parameter (`7A6A3D31`, by role name)
  of a record within two references up or down (lists with more than 64 references are not
  followed).

Outside a coverage run the recording calls do nothing: production reading is unchanged.

Run (no OCCT needed; about 9 minutes for the corpus in a debug build):

```
GUSSET_F3D_SAMPLES=<folder of .f3d/.f3z, searched recursively> \
GUSSET_F3D_COVERAGE=<output folder> \
GUSSET_F3D_OUTCOMES=<log of the f3d_history corpus test run with GUSSET_F3D_VERBOSE=1> \
cargo test -p gusset-cli --test f3d_coverage -- --nocapture
```

It writes `<set>-<number>.txt` per design (every record: `#id tag class @offset len`, then its
spans with names, section-relative offsets, hex and guesses) and `summary.md` (the tables
below). `GUSSET_F3D_OUTCOMES` is optional; it joins each design to its import outcome by file
name. `GUSSET_F3D_ONLY` filters the files by path text.
