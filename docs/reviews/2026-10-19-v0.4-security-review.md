### X1. High: the OpenSCAD evaluator has no memory bound; a tiny file aborts the app [reproduced]

- **Where:** `crates/gusset-scad/src/eval.rs`:
  - `:1130` `concat` builds a vector of any length (no `max_vector` check; only vector
    literals, comprehensions and ranges check it, at `:479` and `:390`);
  - `:649-670` `children_call` with an index list: `idx.into_iter().filter_map(|i| objs.get(i).cloned())`
    deep-copies the child's CSG tree once per index, and `prims` is not counted;
  - `:1140` `str`, `:904` `echo` and `:914` `assert` call `Value::show`, which walks shared
    (`Rc`) nested vectors in full, so the cost is exponential in the nesting;
  - `Limits` (`:25`) has no limit on bytes. ADR 0033 §2 says "50 MB of values".
- **Exploit (T1, the user opens a downloaded `.scad`; or an agent calls `import.file` on a `.scad`
  already in the project folder):** evaluation runs in the app process
  (`import.rs:240`, on the `gusset-import` thread). A Rust allocation failure aborts the process,
  and nothing can catch it. Unsaved work since the last recovery snapshot is lost.
  - `function d(v,n) = n==0 ? v : d(concat(v,v), n-1); x = len(d([1],34)); cube(x);`
    (77 bytes) → `memory allocation of 2147483648 bytes failed`, exit 134. Depth 34 is far below
    the 256 recursion limit, and only about 100 steps are used.
  - `idx=[for(i=[0:999]) 0]; module m() { children(idx); } m() m() m() cube(1);` → 10^9 leaves →
    abort (exit 134). With 100 indices it returns 10^6 leaves in 0.16 s, ten times
    `max_primitives` (see X3).
  - `v0=[1..10]; v1=[v0 x10]; …; v8=[v7 x10]; x=str(v8);` → still running after 120 s, heading for
    a string of about 3 GB.
- **Fix:** keep a byte or element budget in `Eval` (for example 50 M value elements, or the ADR's
  50 MB) and charge every allocation to it: `concat`, `iterate`, binary vector ops, string
  results, `show`. Cap `show`/`str`/`echo`/`assert` output (for example 64 KiB) and stop walking
  past the cap. In `children_call`, count the leaves of every cloned object against
  `max_primitives`, and cap the index list at `max_vector`. Add a fuzz harness with an RSS limit
  (`-rss_limit_mb=2048`), so `scad_read` catches this kind of input.

### X2. High: deep OpenSCAD CSG trees overflow the import thread's stack [reproduced]

- **Where:** `crates/gusset-scad/src/lib.rs:139-150` gives the parser and evaluator a 256 MiB
  thread, but returns the `Model` to the caller. `crates/gusset-commands/src/import.rs:240-251`
  then calls `scad_build::build` (`scad_build.rs:235`, recursive over `Csg::Op`) and later drops
  `model`. Both happen on the `gusset-import` thread, which is spawned with the default 2 MiB stack
  (`crates/gusset-host/src/lib.rs:600` and `:620`). Parser nesting (256,
  `parse.rs:204`) and call depth (256) are limited separately, so their product is not.
- **Exploit:** `module r(k) { if (k>0) { difference(){ difference(){ … 100 levels … r(k-1); cube(1); } … } } else cube(1); } r(250);`
  (about 2 KB) evaluates in 20 ms to a tree about 25,000 levels deep. The harness drops the result
  on a 2 MiB thread: `thread '<unknown>' has overflowed its stack`, `fatal runtime error: stack
  overflow, aborting` (exit 134). With `r(50)` it completes, so the threshold is low. In the app,
  `build` recurses before any kernel call, so the abort comes first.
- **Fix:** limit the CSG depth in the evaluator (for example 512 `Csg::Op` levels: track the depth
  in `combine`/`group`/`extrude`). Build and drop the model on the big-stack thread, or give the
  import thread an explicit large stack. Make `scad_build::build` iterative, or check its depth.

### X3. Medium: OpenSCAD import is not cancellable and its CPU cost escapes the step limit [reproduced]

- **Where:** `gusset_scad::read` takes no cancel flag (`lib.rs:132`). `import.rs:245-247` polls
  `cancel` only between top-level objects. `scad_build::build` makes one kernel call per leaf
  (extrude/revolve plus up to 3 transforms) and one `boolean_many` per operation, with no cancel
  check and no evaluation work budget (ADR 0020). In `eval.rs`, `binary` (`:1015-1050`:
  element-wise `+ - *`, deep `==` / `!=` through derived `PartialEq`) and `iterate` cost one step
  whatever their size.
- **Reproduction:** `w = v9 == v9;` (`v9` = 10^10 shared leaves, built in about 10 steps) takes
  37.6 s in release. The `str` case in X1 runs for more than 120 s. A host's Cancel sets the flag,
  but `ImportJob::run` keeps running until evaluation and the whole build of the current object
  finish. 10^6 leaves from `children()` repeats (X1) means 10^6 primitive builds plus a
  10^6-tool union in the kernel.
- **Impact:** the import never ends from the user's point of view, and Cancel does nothing. The
  CPU stays busy (the kernel worker too). It is not corruption.
- **Fix:** pass the `CancelFlag` into `read_with` and poll it in `step()`. Charge vector ops by
  length (`steps += len`). Count CSG leaves against `max_primitives` after `children` cloning. In
  `scad_build::build`, poll `cancel` per leaf and charge leaves and boolean tools to an evaluation
  `Work` budget, or cap the leaves per import (for example 10,000).

### X4. Medium: FreeCAD import amplifies one shape file and inflates XML before checking its size [traced]

- **Where:** `crates/gusset-commands/src/import.rs:275-297`. `files` deduplicates the read, but the
  loop over `picks` sends each pick's data to the worker, even when many picks name the same
  `file`. `out` keeps every result (`fcstd.rs:216` allows 256 picks). Each worker call may run
  600 s (`gusset-worker/src/lib.rs:679`) and return up to `4 x input + 16 MiB`, at most 1 GiB
  (`output_cap`). `Document.xml`/`GuiDocument.xml` are fully inflated by `read_entries`
  (budget 2 GiB, ratio 200) before `fcstd::document` refuses more than 64 MiB (`fcstd.rs:68`).
  Each `read_entries` call starts a fresh `max_decompressed_bytes` budget
  (`gusset-meshio/src/archive.rs:15`), so the two passes allow 4 GiB.
- **Exploit:** an FCStd of about 6 MB: `Document.xml` lists 256 `Part::Feature` objects, all with
  `<Part file="S.brp"/>` and all visible, and one deflated `S.brp` of about 1 GiB of valid BRep
  text. The worker parses it 256 times, which takes hours of CPU (cancellable). The app keeps up to
  256 output blobs, so it can run out of memory and abort, as in X1. Or `Document.xml` inflates to
  2 GiB from a 10 MB entry: a transient 2 GiB allocation, then a refusal.
- **Fix:** parse each distinct shape file once, and reuse the result for every pick that names it.
  Cap the total worker output kept per import (for example 2 GiB), and the summed worker time.
  Give `read_entries` a per-entry size limit, so XML entries are refused at 64 MiB from the
  declared `usize`, before inflating. Pass one budget across both passes.

### X5. Low: untrusted file text in error messages outside `user_text` [traced]

- **Where:** `eval.rs:914` (`assertion failed: {message}`: the file's own string, any length),
  surfaced by `import.rs:240` as `OpenSCAD: line N: assertion failed: …` in the command error
  `message`. Also `import.rs:299` (`no FreeCAD shape could be read: {labels joined}`: up to 256
  labels of 1,000 characters each), and `commands.rs` `sketch.import_dxf`
  (`'…' cannot be read: bad group code '<20 chars of file>'`).
- **Problem:** THREAT_MODEL B4 promises model text only in labeled `user_text` fields. The
  sanitizer wraps other strings only when its injection heuristic matches, and truncates them at
  512 characters (`gusset-mcp/src/sanitize.rs`). A `.scad` with
  `assert(false, "<paraphrased instructions>")` gives the agent attacker-written text as the
  server's own error message. This is the same class as v0.3 W4.
- **Fix:** put file-derived parts of errors in a `detail_user_text` field (or cap them and put
  them in quotes), and keep `message` to fixed wording. The FreeCAD and DXF warnings are already
  `*_user_text`. Do the same for the errors.

### X6. Low: `sketch.import_dxf` blocks the model thread and cannot be cancelled [traced]

- **Where:** `crates/gusset-commands/src/commands.rs` `SketchImportDxf::run` (around `:1484`).
  `read_capped(file, 64 MiB, &AtomicBool::new(false))`, `dxf_read::read`, up to 50,000 curves into
  the sketch, and `store_solution` all run inside the command, on the model thread.
- **Measured:** parsing a 33 MB file with 999,000 skipped entity types and 49,000 polyline
  vertices took 0.37 s (release). Parsing is cheap. Adding up to about 150,000 points and solving
  the sketch is not measured, and it is the same work the user's later rebuilds do. The reader's
  caps (`MAX_ENTITIES`, `MAX_GROUPS`, `MAX_CURVES`, finite numbers below 1e12) hold.
- **Fix:** route DXF through the import pipeline (`begin_import` / off-thread `run` with the
  real cancel flag / `complete_import`). Refuse files whose curve count would take the sketch past
  `gusset_sketch::MAX_ENTITIES` before editing. Bound `scale` (for example to `1e-6..1e6`), so
  `p * k` cannot overflow to infinity before `add_point`'s checks.

### X7. Info: FreeCAD binary shapes always fail [traced]

- `import.rs:287` passes `"brep"` for `*.bin`. `WorkerImporter::import` maps names with
  `Format::from_extension` (`gusset-worker/src/lib.rs:52-58`), which knows only `brp`/`brep_text`.
  The import fails with "'brep' is not imported by the worker". This fails closed, and nothing is
  parsed in the app process. If it is fixed, map it to `Format::Brep` (BinTools in the worker),
  never to an in-process read.

### X8. Info: threat model and ADR claims not updated [verified]

- `docs/THREAT_MODEL.md` names FCStd and `.scad` in T1 only. No boundary row covers in-process
  OpenSCAD evaluation (the one import that runs untrusted program logic in the app process), the
  in-process FCStd ZIP/XML reading, DXF into sketches, or drawing exports (`writes_files`).
- ADR 0033 §2 says evaluation is bounded at "50 MB of values", but `Limits` has no such field
  (see X1).
- **Fix:** add the rows, and correct the ADR once X1 is fixed.

## Checked and found sound

- **ZIP reader** (`gusset-meshio/src/zip.rs`, `archive.rs`): entry names are checked (absolute
  paths, `..`, control characters); FCStd entry names are only compared, never used as paths, so
  path traversal cannot happen. Duplicate names (ignoring case) are refused. There are caps on the
  entry count (10,000) and on declared-size ratio (200 above 1 MiB). Inflation is limited to the
  declared size + 1, and the CRC is checked. Encrypted and unknown methods are refused, and ZIP64
  fields are bounds-checked. Overlapping-entry bombs are charged per entry against the budget
  (but see X4 on the budget per pass).
- **FCStd XML** (`fcstd.rs`): quick-xml does not process DTDs or external entities; unknown
  entities fail `normalized_value`, which is dropped (`.ok()`). Attribute values are cut to 1,000
  characters, with at most 20,000 objects and 10,000 links per object. Labels go to
  `label_user_text` and are quoted by `gusset_doc::cursor::quote` (newlines and quotes escaped) in
  the code view.
- **BRep text** is parsed only in the sandboxed worker (`gusset-worker/src/main.rs:75`, the only
  caller of `safe::brep_text_read`). The worker walks the topology and re-serializes with
  BinTools. The app parses only the worker's output.
- **OpenSCAD** `include`/`use`/`import()` are never followed (a warning only), so no file outside
  the import is read. `$fn` does not change the geometry size (true surfaces). Recursion and parse
  depth are limited, and parsing runs on a 256 MiB stack.
- **DXF reader** (`dxf_read.rs`): streaming, caps on entities, groups, vertices and curves, finite
  numbers below 1e12, binary DXF refused, skipped type names cut to 32 characters and returned
  (20 at most) as `skipped_user_text`.
- **Writers:** SVG text is XML-escaped (`& < > " '`, control characters dropped). PDF strings are
  literal-escaped (`( ) \` and octal for bytes outside 0x20-0x7E), the title included. DXF text
  drops controls (so no group-structure injection by newline), escapes `%`, and writes
  non-ASCII as `\U+XXXX`. Layer and table names are constants. U+FFFE/U+FFFF pass through SVG
  `esc` (XML-invalid, harmless).
- **`drawing.export`:** the `WRITE_FILE` flag (refused for read-only agents), `export_target` with
  agent confinement and an extension allow-list (`svg`/`dxf`/`pdf`) matching the format, and
  overwrites that need `overwrite: true` plus approval for agents. Writes go through
  `durable_write` (atomic replace, so a symlink target is not followed). Drawings are limited to
  200 views (below the 256-entry HLR cache) and 10,000 items, and builds are stoppable (D3).
- **Raster:** at most 4096 px a side, 100,000 dash quads.
