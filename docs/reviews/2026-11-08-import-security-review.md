# Security review: assemblies, OpenSCAD features and image export (2026-11-08)

Read-only review of the commits of 2026-11-08 `6fd74ea`, `2c0e93e` (SolidWorks assemblies and
virtual components), `d598254` (OpenSCAD objects as features), `fe94336`/`a57d481`/`af89566`
(Fusion placements, helical surfaces) and `473568d`/`152e89d` (`export.image`, appearance
textures). Threat model: `docs/THREAT_MODEL.md` T1 (hostile files) and T5 (an agent with
limited rights). Nothing was fixed in this review.
"Verified" means a throwaway program outside the repo (scratch crate, release build, public
API plus `Session`/`execute("import.file")` with a double `Importer` and the mock kernel)
reproduced the finding. The sources are in the reviewer's scratch directory
(`scratchpad/secreview/src/{asm,scad,fus,rt}.rs`); a chunk container with a crafted
`COMPINSTANCETREE` is about 40 lines.

## Suggested fixes
- **S1**: cache the parsed sub-assembly by file name (like `parts`) and keep one `Arc<Assembly>` per file; push `(Arc, placement)` only. Count instances when pushing, not when popping. Add a budget on total parsed components over the import.
- **S2**: bound the instance-list walk by a per-stream step budget (for example 2 M steps over all records) and check `cancel` inside `transforms`; reuse the previous record's list when a record starts inside it; give `nested_loose` a precomputed sorted index of `rigid_at` hits instead of scanning 3000 bytes per call.
- **S3**: keep a per-base counter in `Gen` (a `HashMap<String, usize>` of the next number) and probe from there; or number objects in the job and not at commit.
- **S4**: convert each (file, configuration) once and place copies by transform or by an instance in the document; count failed conversions against a budget (for example 16) and stop the import after it; cache `embedded_part` by stream name.
- **S5**: send the notes in `warnings_user_text` details, keep `message` a fixed text ("no component of the assembly could be imported", count of notes), and strip control characters from names at parse time.
- **S6**: `tail.get(..12).and_then(|t| t.find(';'))`.
- **S7**: build the three lookup maps once with the listing.
- **S8**: as in the table; and document the rule in THREAT_MODEL B2.
- **S9-S11**: no change needed; note the limits in the ADR if desired.

## Checked and sound
- **Path traversal in `Folder`**: a name with `/`, `\`, `:` (drives, `C:x`, alternate data streams), NUL, `.` or `..` is refused before any lookup; the name is then only *matched against the folder's own listing* and the listing's spelling is opened, so Windows aliases (trailing dots and spaces, 8.3 names, device names) never reach the file system. Sub-folder files are not found by a plain name. `open_regular` uses `O_NOFOLLOW|O_NONBLOCK` (Windows: open reparse point) and checks the handle: a symlink or FIFO named as a part is refused (`not_allowed`), a directory is refused. The repo's own test covers the separator cases.
- **Agent confinement for the assembly itself**: `read_target` -> `confined` canonicalises the parent, so the folder searched for parts (`full.parent()`) is inside the project folder for an agent. For the user any folder they chose is searched; that is their file.
- **Case and normalisation tricks**: exact, then ASCII case-insensitive, then lower-case with spaces as underscores, all against the same listing, so the worst case is the wrong sibling in the same folder.
- **Nesting**: depth at most 4 (`MAX_SLDASM_DEPTH`); a self-referencing assembly stops at that depth and at the instance cap; instances 2000 per import; components 20 000 per assembly; 2 000 000 XML tags; attribute values 4096, 64 attributes per tag.
- **XML scanner** (`assembly.rs`): no DTD, no external data, only the five predefined and numeric entities (invalid code points dropped); every index is `get`-checked, truncated and noisy inputs are in the repo test (`hostile_assembly_trees_stay_bounded`); unterminated tags, comments and quotes end the scan (linear). Slicing a truncated value on a non-boundary yields an empty string.
- **Numbers**: `numbers::<N>` rejects non-finite values and a wrong count; `rigid` re-checks orthonormality, determinant and a translation bound, so mirrored/scaled/NaN placements are skipped with a note, never imported.
- **Names into STEP**: `gusset-xt` `string()` keeps printable ASCII only and replaces `'` and `\`; `to_step_placed` composes with the body's own placement and is covered by a test. Body labels from component names are cut to 200 characters and written escaped by the document writer (verified: quotes, backslashes, newlines, NUL, CR, bidi marks all round-trip as `\n`, `\u{0}`, ... and `Document::from_text(to_text())` is equal).
- **Virtual components**: `embedded_part` only accepts names starting with `VirtualComp/` and compares them with the streams of the same file; the name never reaches the file system.
- **OpenSCAD features**: the generated text contains only fixed keywords, names produced by `fresh` (`Base<n>`) and numbers from `num()`, which refuses NaN, inf and anything above 1e9, trims to nine decimals and never prints an exponent. No string from the `.scad` file reaches the text, so there is no statement injection; I generated text for NaN, inf, 1e300, 1e308, 1e9, 1e-320, -0 and tiny shapes: every output parsed, and every line is a `sketch`/`extrude`/`revolve`/`move`/`combine` statement. Counts are capped per object (5000 curves, 2000 features). `commit_import` replaces the document by `parse(to_text() + features)` inside `edit`; a failed parse is an error and the edit is not applied. The names are checked against feature and parameter names (a name clash with another namespace would only fail the parse).
- **Scratch evaluation** in the import job (`check`) is cancellable through the job, uses a fresh `Evaluator` on a throwaway document, and compares volume and box before the features are accepted.
- **`export.image`**: size 1..4096, samples 1..1024, width x height x samples at most 2^26 paths; view from a fixed list; `.png` required; the target goes through `export_target` (agents: confinement, hidden names, device names, extension list; the `png` extension is passed explicitly), refuses to write through a symlink, asks for approval to overwrite when an agent has approvals on, and is written with `durable_write` (random temp name, rename). Rendering stops with the session's cancel flag (checked per row) and the scene has a top-level BVH, so review S10 (work per ray linear in meshes) no longer applies. Meshes are cloned for the renderer (twice the memory of the scene), which is within the usual model limits.
- **`body.appearance` textures**: `texture` must be one of four keywords or `none`; `texture_size` is finite and 0.01..10000 mm, converted with a range check; error messages echo the value with control characters removed and cut to 40; the document text parser checks the same range. The renderer divides by `size_um.max(1)`.
- **Fusion**: `component_parts` and `component_groups` are bounded (256 components, run gap 700, 4096 repeats, indexes via `partition_point` and `get`); no panic paths (`groups.len() - 1` is guarded by the non-empty check). `helix_surface` refuses non-finite ranges, tapered helices, and `helix_fit` limits turns to 500; `MAX_SURFACE_CANDIDATES` bounds the retry loop; STEP output is capped at 256 MiB.
