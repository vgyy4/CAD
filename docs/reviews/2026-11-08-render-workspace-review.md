| R1 | M | **Photo preview is not stopped when a sketch is edited from the Render tab.** `Action::SketchTab` (and `edit_sketch` from a double click in the tree) does not clear `render_tab` or call `photo.set(false)`; only the Solid/Surface/Sheet/Cam tabs do. The overlay condition is `self.render_tab && self.photo.on` (app.rs ~3242), so with the preview on, clicking the Sketch tab paints the traced picture over the sketch editor (sketches are drawn by `viewport.show` before the overlay) and the user draws blind. Only Finish sketch (SolidTab) clears it. | Also require `self.sketch.is_none() && self.active_drawing.is_none()` in the overlay condition, or call `self.photo.set(false)` in `SketchTab`/`edit_sketch`/`open_drawing`. |
| R2 | M | **The preview's cache key is the scene's address, so edits made in place leave a stale picture.** `key = format!("{:p} {camera:?} {size:?}", Arc::as_ptr(&scene))` (photo_preview.rs). The viewport mutates its scene through `Arc::make_mut` without changing the address when no other `Arc` is alive: `set_body_visible` (eye toggle) and `apply_highlights` (hover/selection). After the worker has finished its four passes it has dropped its clone, so hiding a body leaves the old picture, body still shown, until the camera moves. The reverse also happens: while a pass runs, the worker's clone makes every hover change `make_mut` a copy (new address), which restarts the passes and drops the texture, so the preview never converges while the pointer moves over faces. Hover also bakes the `Preselect` colour into the traced image (trace.rs colours `Highlight::Preselect`), and once the passes are done that colour stays until the camera moves. | Key on `viewport.revision`/`generation` (both exist and are bumped by exactly these mutations) instead of the pointer; send the worker a scene with highlights cleared (or have the tracer ignore `Preselect`). |
| R3 | M | **`export.image` can occupy the session for minutes and cannot be cancelled.** Limits are 4096 x 4096 px and 1024 samples, bounded only by `MAX_PATHS` = 4e8 paths in `render_traced`. `renderer.photo()` runs inside `Command::run` with `&mut Session`, so the model thread and every other command wait. Measured: the debug CLI path-traces 256 x 256 x 16 (1.05 M paths) in 7.5 s on 4 cores; a request at the cap is about 400 x that, and even the default 1280 x 800 x 32 (33 M paths) is 30x. No progress, no cancel, no timeout. An agent can stall the GUI's command queue with one call (release is faster, but the order of magnitude holds). | Lower the agent-facing cap (for example 16 M paths, as `render_view` caps samples at 256 and size at `MAX_RENDER_SIZE`), render off the session lock like imports do, or poll a cancel flag per row band in `render_traced`. |
| R4 | L | **Abandoned preview passes keep running.** `stop()` only bumps the generation; the worker checks it between passes, not inside `render_traced`, which itself spawns one thread per core. A pass of 64 spp at half resolution that is already running finishes (seconds) while the next generation's pass starts, so several all-core traces overlap after quick view changes or the hover restarts of R2. Passes also re-render from scratch (1+4+16+64 = 85 spp of work for a 64 spp picture). A render error ends the worker silently (`let Ok(img) = ... else return`), leaving the previous picture with no sign. | Pass a cancel flag into the tracer's row loop; accumulate passes instead of re-rendering; show the error in the Render tab. |
| R5 | L | **App "Render image" can be started twice.** `render_to` overwrites `self.render_job` with a new receiver without checking the old one; the first thread keeps tracing (1600 x 1200 x 64 = 123 M paths by default) and its result and written file are never reported. It also clones the whole `Scene` on the UI thread (`self.viewport.scene().clone()`), including hover highlights. | Refuse while `render_job.is_some()`; clone the `Arc` (`scene_arc()`). |
| R6 | L | **A texture cannot be resized without repeating its kind.** `body.appearance {texture_size: 8}` on a body that already has `texture: wood` fails with "texture_size needs a texture" (`texture_choice`). Switching kind without a size silently resets to the new kind's default size. | When `texture` is absent and `texture_size` is given, apply it to the body's current texture (error only if it has none). |
| R7 | N | **Merge treats colour, finish and texture as one unit.** `merge_look` picks the `(color, finish, texture)` tuple three-way, so ours changing the colour and theirs adding a texture is a conflict (resolved by `prefer`/ours) rather than combining. This is the same behaviour colour+finish already had, so it is consistent, but the doc comment says "two parts" and no test covers texture. | Pick the three fields separately and add a merge test (colour vs texture; texture vs face colours). |
| R8 | N | **STEP export notes that finishes are lost but says nothing about textures** (commands.rs ~3578 checks `finish` only). Textures are also not written to any mesh format. | Extend the note to `a.texture.is_some()`. |

## Checked and sound

- **export.image path safety.** Agents go through `export_target` -> `confined` (no absolute paths, `..`, backslashes, canonical-parent check against the project root, no write through a symlink target) then `agent_export_name` with `["png"]`: hidden components, device names, trailing dots, ADS characters, extension allow-list. The extension is also checked before any work. Overwrite needs `overwrite: true` and, for agents with approvals on, an approval. Writes go through `durable_write`. Error messages carry the given relative name, not absolute paths. The user actor may write anywhere, as for every other export.
- **Parameter bounds.** Width/height 1..=4096, samples 1..=1024, view from a fixed list (lower-cased, trimmed), `deny_unknown_fields`; `render_traced` re-checks size, samples and the 4e8 path cap, so no overflow or allocation beyond 4096 x 4096 x 4 bytes. `u32` products are done in `u64`.
- **Renderer registration.** CLI (also `gusset mcp`) and app both register the renderer; an unregistered build answers `not_allowed`, not a panic. `photo()` rebuilds the same scene as `render_view`, textures included (`render_material`).
- **Text round trip of `texture_size`.** `size_um / 1000.0` printed with `{}` never uses an exponent and always has at most three decimals, so the parse (`round(v * 1000)`) returns the same micrometres. Checked through `gusset pack` then `gusset text` for `0.01`, `1e-2`, `0.015`, `1.0000001`, `9999.999`, `10000` and `8mm`: all print canonically and re-parse; `0.0049` is refused with a position. The default size is omitted on print and restored on parse; `texture_size` without `texture` is a parse error; NaN is refused by the command and cannot occur in text.
- **Command validation.** `texture_size` is finite and range-checked in micrometres before `as u32`; `clear` with a texture, `texture: none` with a size, and face colours with a texture are all refused with hints; `none` removes the texture and keeps colour and finish.
- **Rust vs WGSL.** Hash constants and shifts, `noise3`/`fbm` (octave scale 2.03, amplitudes, 1.75 gain), the wood, brushed, carbon (axis choice, `(i+j) mod 4 < 2`, tone and bulge) and speckle formulas, offsets (3.7, 5.3, 17/-31/7 ...), the 0..1.6 clamp and the 0.98 albedo cap match line for line. Float-to-int conversion saturates in both for the hash. The `Draw` uniform grew from 4 to 5 vec4 with `DRAW_SIZE` and the dynamic stride updated together; edge draws get a zero word. Differences left are the f32 precision, interpolated vs geometric normal for the carbon plane choice, and the tracer's per-hit barycentric position; all within the GPU-vs-software test tolerance.
- **Texture application.** Only runs in the material's own colour are textured (`texture_for`, the tracer's `color == base`), so face colours and highlights are not overwritten; section caps are untextured; clipped triangles interpolate `model`/`model_normal` along with the other attributes.
- **Photo preview threads (apart from R2/R4).** Stale results are dropped by generation; the receiver is replaced on restart so old senders fail and exit; `moving` stops and waits; once the last pass is in nothing runs and nothing requests repaints (no busy loop); turning the preview off clears texture and key. The UI thread only uploads textures.
- **Ribbon icons.** Painted from fixed polygons; no indexing or panics; the Render tab is excluded from the Solid tab's active test.
